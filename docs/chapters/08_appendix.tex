Изисква се компилатор за C++20 и CMake 3.20 или по-нов. Външни зависимости няма и по време на
конфигуриране не се тегли нищо. \code{ctest} докладва 10 записа и 125 отделни случая, а
\code{trident\_demo} зарежда генерирания набор, изпълнява десет заявки и за всяка отпечатва
алгебричното дърво, избрания план, броя решения и изтеклото време.

\begin{lstlisting}[language={},caption={Изграждане, тестове, демонстрация и измервания}]

build/trident_demo
build/trident_bench --repeats 15
\end{lstlisting}

\subsection*{Приложение Б. Поддържано подмножество на SPARQL}

\textbf{Разпознава се:} \code{PREFIX} и \code{BASE}; \code{SELECT} с изброени променливи или
\code{*}; \code{DISTINCT} и \code{REDUCED}; базови графови шаблони със съкратени списъци и с
ключовата дума \code{a}; литерали с езиков етикет и с тип; празни възли във вид
\code{\_:етикет} и \code{[]}; вложени групи; \code{OPTIONAL}; \code{UNION}; \code{FILTER};
\code{GROUP BY} по променливи; \code{COUNT}, \code{SUM}, \code{MIN}, \code{MAX}, \code{AVG} и
\code{SAMPLE}, със и без \code{DISTINCT}; \code{ORDER BY}, \code{LIMIT} и \code{OFFSET}. В
изразите: \code{||}, \code{\&\&}, шестте сравнения, четирите аритметични операции, унарни
\code{!} и \code{-}, и 25 функции, сред които \code{BOUND}, \code{STR}, \code{DATATYPE},
\code{isIRI}, \code{STRLEN}, \code{CONTAINS}, \code{SUBSTR}, \code{REGEX} и \code{COALESCE}.

\textbf{Отхвърля се с изрична грешка:} \code{ASK}, \code{CONSTRUCT}, \code{DESCRIBE},
\code{GRAPH}, \code{SERVICE}, \code{MINUS}, \code{BIND}, \code{VALUES}, \code{HAVING},
подзаявки, пътища по свойства, \code{GROUP BY} по израз и всяко име на функция извън списъка.
Всеки от тези случаи има отрицателен запис в набора от синтактични случаи, тоест границата на
подмножеството е проверявана, а не само описана.

\subsection*{Приложение В. Заявки, използвани при измерванията}

Всички заявки започват с \code{PREFIX ex: <http://example.org/>}, пропуснат по-долу.

\begin{lstlisting}[language={},caption={Работно натоварване}]
B1  SELECT ?p ?t WHERE { ?p ex:title ?t }
B2  SELECT ?t ?y WHERE { ?p ex:title ?t . ?p ex:year ?y }
B3  SELECT ?t ?n WHERE { ?p ex:title ?t . ?p ex:mainAuthor ?a .
                        ?a ex:name ?n . ?a ex:affiliation ex:org3 }
B4  SELECT ?t ?n WHERE { ?p ex:title ?t . ?p ex:mainAuthor ?a .
                        ?a ex:name ?n . ?a ex:affiliation ex:org3 .
                        ?p ex:venue ex:venue2 }
B5  SELECT ?p WHERE { ?p ex:citationCount ?c FILTER (?c > 100) }
B6  SELECT ?n ?h WHERE { ?a a ex:Author . ?a ex:name ?n
                        OPTIONAL { ?a ex:homepage ?h } }
B7  SELECT ?v (COUNT(?p) AS ?n) WHERE { ?p ex:venue ?v } GROUP BY ?v
B8  SELECT ?p WHERE { ?p ex:citationCount ?c } ORDER BY DESC(?c)

Стратегия на съединяване:
    SELECT ?a ?first ?second WHERE { ?first ex:mainAuthor ?a .
                                     ?second ex:author ?a }
\end{lstlisting}
